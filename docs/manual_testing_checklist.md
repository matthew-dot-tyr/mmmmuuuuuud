# Ручная проверка: кастомные ситуации, вход по magic link, стрик

Чек-лист по всему, что добавлено в этой ветке. Пункты идут в порядке, в
котором имеет смысл проверять — каждый следующий опирается на предыдущий.

## 0. Предварительно

- [ ] `.env` заполнен: `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_JWT_SECRET`, `OPENROUTER_API_KEY`
- [ ] В Supabase накатаны миграции **по порядку**: `001_users.sql` → `002_negotiations.sql` → `003_custom_situations.sql` → `004_attempts_streak.sql` (SQL Editor → New query → вставить файл → Run)
- [ ] Желательно задать `SESSION_SECRET` в `.env` — без него любой перезапуск/reload сервера рвёт все незакрытые переговоры (это старое поведение проекта, не новое)
- [ ] Сервер запущен: `uvicorn main:app --reload`, открыт `http://127.0.0.1:8000/play`

Если пункт с `004_attempts_streak.sql` пропустить — всё остальное всё равно
работает, просто `/attempts` будет пустым списком, а бейдж стрика не появится
(мягкая деградация, не ошибка — см. `[warning]` в логе сервера).

## 1. Вход по magic link

- [ ] На `/play` виден экран «Вход» — поле email и кнопка «Прислать ссылку для входа»
- [ ] Ввести почту → нажать кнопку → появляется «Проверьте почту»
- [ ] Перейти по ссылке из письма (в той же вкладке/браузере)
- [ ] Результат: адресная строка чистая (без `#access_token=...`), в шапке видно «игрок XXXXXXXX», показан уровень/XP — **без единого клика руками**, кроме перехода по ссылке
- [ ] Обновить страницу (F5) — сессия должна остаться (не разлогинивает)
- [ ] Нажать «выйти» — возвращает на экран входа

Если письмо не пришло — проверить «Спам»; на бесплатном тарифе Supabase есть
лимит писем в час (`email rate limit exceeded`), тогда просто подождать.

## 2. Переговоры по теме

- [ ] Выбрать «Готовая тема» → любую тему → «Сложность 1» → «Начать переговоры»
- [ ] Появляется сценарий, реплика оппонента, 3 варианта ответа
- [ ] Дойти до конца (несколько ходов) → экран итога: вердикт (Успех/Провал), оценка, **структурный разбор** (не голый текст: «Где сломалось» / «Что сработало» / «Совет» отдельными строками)
- [ ] XP начислился, при накоплении 100 — «Новый уровень!»
- [ ] Бейдж 🔥 наверху стал «1 день подряд» (если раньше не играли сегодня)
- [ ] Внизу появилась карточка «Последние попытки» с этой записью (тема + дата + зелёная/красная точка по исходу)

## 3. Своя ситуация (custom)

- [ ] Переключиться на «Своя ситуация», ввести описание 30–400 символов (например: «Хочу договориться с соседом, чтобы он не шумел после десяти вечера»)
- [ ] Счётчик символов под полем считает корректно, кнопка «Начать переговоры» неактивна при < 30 символов
- [ ] Отправить — генерируется сценарий (тема будет отражать вашу ситуацию, не из списка)
- [ ] Попытка тоже появляется в «Последних попытках», с темой «Своя ситуация»

## 4. Отказы (не должны ронять страницу)

Все три — в режиме «Своя ситуация», сразу должен показаться текст ошибки
(не белый экран, не исключение в консоли):

- [ ] Короткий текст (< 30 символов) → «Опишите ситуацию подробнее»
- [ ] Текст со ссылкой (`...https://example.com`) → «Уберите ссылки»
- [ ] Текст не про переговоры («напиши мне стих про осень») → модель отклоняет с понятным объяснением (`not_a_negotiation`/`too_vague`)

## 5. Сложность 3 (свободный текст)

Нужен 3-й уровень персонажа (набрать XP или временно поднять `xp` игроку в
Supabase вручную для теста). На сложности 3 вместо вариантов — текстовое
поле, ответ печатается свободно.

## 6. Межпользовательская проверка (по желанию, через два браузера/профиля)

- [ ] Войти под двумя разными почтами в двух окнах
- [ ] Убедиться, что прогресс, попытки и стрик — раздельные, чужие данные не видны

## 7. Что нельзя быстро проверить руками (уже покрыто автотестами)

- Рост стрика на второй день подряд и сброс после пропуска — требует
  реального ожидания суток; логика проверена в `tests/test_progress.py`
  (`compute_streak`) и `tests/test_api.py` с подменой даты.
- Лимит генераций в час (10 кастомных / 30 тематических на пользователя) —
  требует 10+ реальных стартов подряд; логика в `rate_limit.py`, тест —
  `tests/test_api.py::test_start_rate_limited`.
- 401/403 на отсутствующий/чужой/просроченный токен — `tests/test_auth.py`,
  `tests/test_api.py::test_negotiation_requires_real_bearer_token`.

Быстрый способ проверить 401 руками — открыть `/play` в приватном окне без
входа и попробовать вызвать `fetch('/user/me')` в консоли браузера: должен
вернуться 401.
